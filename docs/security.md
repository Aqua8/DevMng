# 보안 메모

개인용 로컬 전용 포털(`127.0.0.1`에서만 접속)을 기준으로 점검한 결과와, 일부러 남겨 둔 위험을 기록한다. 점검일 2026-10-07.

## 지켜 둔 것

- **MCP는 읽기 전용 도구 2개만** 노출한다(`docs/mcp.md`). 토큰은 `mcp-actions`, `botmng` 플러그인에만 접근하고, 카탈로그·scaffolder 직접 호출은 403이다.
- **BotMng 서비스 계정은 `/api/health`만** 쓴다. 화면 로그인은 막혀 있고 토큰은 15분만 유효하다.
- **비밀 값은 커밋·이미지에 없다.** `.env`, `*.local.yaml`은 git과 `.dockerignore`에서 제외되고, 커밋 이력 전체를 검색해 비밀 값·개인 경로를 찾지 못했다.
- **서비스 비밀번호가 담긴 요청**은 리다이렉트를 따라가지 않고(`redirect: 'error'`), `https`가 아닌 BotMng 주소(내 컴퓨터로 향하는 `http`는 예외)는 설정 없음으로 본다. 틀린 비밀번호로는 1분 동안 다시 로그인하지 않는다.
- **응답에 내부 정보가 없다.** 연결 오류 원인(주소 등)은 숨기고 고정 문구만 낸다. MCP로 LLM에 전달되는 `issues`는 20개, 항목당 200자로 제한한다.
- **컨테이너**: `node` 사용자로 실행, `no-new-privileges`와 `cap_drop: ALL`, 포트는 `127.0.0.1`에만 바인딩, 운영 설정은 CSP `connect-src 'self'`와 같은 출처 CORS만 허용.
- **CI**: `pull_request` 트리거(포크 PR에 비밀 미전달), 읽기 권한만, 액션은 커밋 해시로 고정, `persist-credentials: false`.

- **`.env` 파일 권한**: BotMng와 DevMng의 `.env`는 `600`(소유자만 읽기)이다.

## 일부러 남긴 위험 (로컬 전용 가정)

- **게스트 로그인은 비밀번호가 없고 권한 정책은 모두 허용**이다. 로컬 전용 가정이 깨지면(예: DNS rebinding, 포트를 0.0.0.0에 연 경우) 게스트가 카탈로그 위치 등록·삭제, scaffolder 실행을 할 수 있다. 인터넷에 열 계획이 생기면 먼저 접속 경로를 제한하고(VPN/터널, Cloudflare Access) 실제 인증과 읽기 전용 권한 정책을 붙인다(`docs/docker.md`).
- `GITHUB_TOKEN`을 설정하면 게스트도 그 토큰으로 비공개 저장소의 catalog-info를 읽을 수 있다. 설정하지 않았고, 설정한다면 최소 권한 토큰만 쓴다.
- 이미지 태그(`node`, `postgres`)를 digest로 고정하지 않았고 Postgres 접속은 `postgres` 슈퍼유저다.
- 상태 조회는 요청마다 BotMng를 호출한다(결과 캐시 없음). 카드는 30초마다 한 번이다.
- `docker inspect`에는 환경 변수가 보인다(이 컴퓨터의 로컬 사용자 한정).

## BotMng 쪽 조치

점검에서 BotMng 쪽 개선 항목이 나왔다. 코드 변경이 필요한 것은 BotMng 저장소에서 다룬다.

- **비밀번호 강도 (조치 완료, BotMng PR #16)**: 관리자·서비스 계정 비밀번호가 6자리 숫자이고 서로 같았다. 서버가 시작할 때 12자 이상, 계정끼리 서로 다른 값인지 검사하고 어기면 시작을 거부한다. 세 비밀번호를 서로 다른 값으로 교체했고, 이전 서비스 비밀번호로는 더 이상 관리자 로그인이 되지 않는 것을 확인했다.
- **로그인 처리율 제한 (조치 완료, BotMng PR #18)**: 점검에서는 "IP당 분당 10회를 login, guest, service, resume이 한 버킷으로 공유한다"고 지적했지만 코드로 확인하니 사실이 아니었다(`@nestjs/throttler`가 핸들러별로 따로 집계). 사실이던 두 가지를 고쳤다: 직접 구현한 추적기에서 빠져 있던 IPv6 /64 묶음(주소를 바꿔 제한을 피할 수 있었음)과 계정 단위 잠금(같은 계정에서 15분 안에 10번 실패하면 15분간 429, 없는 아이디도 똑같이 집계). 운영 서버에서 확인했다(10번 실패 뒤 429, 대소문자·공백 변형도 429, 다른 계정과 정상 로그인은 영향 없음). 한계: 메모리에만 저장돼 재시작하면 초기화되고, 일부러 실패를 쌓아 정상 사용자를 15분 막을 수 있다. 15분 뒤 해제는 단위 테스트로만 확인했다.
- **`/api/health`의 `accessLogCount` (미조치)**: 서비스 계정 접속 행을 포함해, 게스트가 보이는 접속 로그 합계와 비교해 서비스 접속 빈도를 추정할 수 있다.
- 서비스 계정이 없거나 비어 있을 때와 틀렸을 때의 응답 시간 차이(bcrypt 비교 생략), JWT의 DB 재확인·알고리즘 고정 (미조치).

## `.env` 값 주의: `#`과 `$`

비밀번호에 `#`이 들어 있고 따옴표가 없으면 dotenv가 그 뒤를 주석으로 보고 **잘라서 읽는다.** 입력한 값이 아니라 앞부분이 실제 비밀번호가 되어, 입력한 전체 값으로 로그인하면 실패한다. 실제로 BotMng의 DB 비밀번호와 관리자 비밀번호에서 두 번 겪었다. `#`이나 `$`가 들어 있으면 값을 큰따옴표로 감싼다. 값을 바꾼 뒤에는 앱이 읽는 길이와 입력한 길이가 같은지 확인한다. 또한 BotMng와 DevMng는 서로 다른 파서(dotenv, docker compose)로 `.env`를 읽으므로 특수문자를 피하거나 두 곳에서 같은 값으로 읽히는지 확인하는 것이 안전하다.
